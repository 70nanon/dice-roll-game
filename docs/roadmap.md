# ローグライト化ロードマップ

現在のシンプルな CPU 対戦チンチロを、**段階的に**ローグライトへ発展させるための大まかな方向です。

最終形をいま設計することは目的にしていません。各 Phase の詳細は、その Phase に着手するときに決めます。

## 0. 読み方と原則

- **一度に全部実装しない**。Phase 単位で少しずつ進める
- **既存のチンチロとしてのルール・遊びやすさを維持する**。発展のために今の遊びが壊れるなら、その変更は分ける
- **今必要のない機能を先回りして実装しない**。将来を予測した抽象化もしない
- 仕様変更や新ルール追加は今後も大量に起きる前提。**このドキュメントの Phase 2 以降は「変わるもの」として読む**
- 各 Phase で既存テストを維持し、必要なテストを追加する（[AGENTS.md](../AGENTS.md)）

実装順の判断はこのドキュメントを優先します。[追加機能バックログ](backlog.md) は候補置き場で、ロードマップと重複する項目はロードマップ側の順序に従います。

## 1. 発展イメージ

```text
普通のチンチロ                     ← Phase 0（ほぼ完了）
  ↓
敵を破産させるゲーム               ← Phase 1
  ↓
敵との連戦                         ← Phase 2
  ↓
勝利するたびに強化される           ← Phase 3
  ↓
ランごとに異なるビルドが形成される ← Phase 4
  ↓
遊びながらルールを追加             ← Phase 5（未定）
```

## 3. Phase 1: 敵を「倒す」

CPU にも所持金を持たせ、プレイヤーと奪い合う。

- CPU の所持金が 0 になったら、その CPU を撃破
- プレイヤーの所持金が 0 になったらゲームオーバー
- HP や攻撃力などの別パラメータは作らない。**所持金 = 生存リソース**

着手時に決めること（現時点では未決のままにする）:

- CPU の初期所持金をいくらにするか
- プレイヤーの勝ち額が CPU の所持金を超えるときの扱い（CPU の残高までしか払えない、で撃破とするか）
- 撃破後に何を出すか（Phase 2 が入るまでの暫定表示）

決まっていること:

- **試合制（無制限 / 5 / 10 ラウンド）はやめる**。終了条件を撃破と破産に一本化し、ラウンド数の選択 UI（`MatchLengthPicker`）と `matchLength` / `matchOver` を落とす。「規定ラウンドで終わる」と「敵を破産させるまで戦う」を両立させるとフェーズと画面が増えるため

## 4. Phase 2: 連戦

- CPU 撃破後、次の Battle へ進む（Battle 1 → 2 → 3 …）
- プレイヤーの所持金は次の Battle へ持ち越す
- 後の Battle ほど CPU の初期所持金を増やす

強さの基準は「敵の初期所持金が多いほど強い」だけにする。Minimum Bet の上昇は必要になったら検討する。**難易度システムを先回りして作らない。**

## 5. Phase 3: ローグライト化

- CPU 撃破後にランダムな報酬候補を 3 つ提示し、1 つ選ぶ
- 強化は現在のラン中のみ有効。ゲームオーバーで全部失う
- 最初の候補はチンチロのルールから離れないもの（例: 6 の目で勝ったときの倍率 ×1.5、シゴロの倍率アップ、ゾロ目の倍率アップ）

着手時に注意する点:

- 現在の倍率は「勝者の役の倍率」と「敗者が負う倍率」の**大きい方**を採る（`src/domain/payout.ts`）。ここに ×1.5 のような乗数が入ると小数が出るので、**端数の扱い（切り上げ / 切り捨て / 四捨五入）を決める必要がある**
- `Settlement.multiplier` は結果の文言に `${multiplier}倍` として直接出ている。倍率が小数になると表示も影響を受ける

## 6. Phase 4: ビルド要素の拡張

通常ダイスの一部を特殊ダイス（強欲 / 安全 / 博打など、面の構成が違うダイス）に交換できるようにする案。

入手方法・所持数・交換ルールは、この Phase に着手するときに決めます。**現時点では実装しません。**

## 7. Phase 5: 未定

事前に仕様を固めません。遊びながら面白そうなものを足します。候補: ショップ、ボス、敵固有能力、ランダムイベント、永続アンロック、新しい役、イカサマ要素、その他の特殊ルール。

構想段階であり、実装対象ではありません。

**いま直す必要はない**が、該当 Phase に入るときに最初に見る場所です。先回りの修正はしません。

| # | 箇所 | 内容 | 効いてくる Phase |

## 9. 進め方

- 1 Phase = 1 PR ではない。[AGENTS.md](../AGENTS.md) のとおり PR は小さく分ける
- ルールを変えたら [実装計画](implementation-plan.md) のルール定義も同じ PR で更新する
- Phase が進んだら、このドキュメントの状態（セクション 2 の表など）も更新する
- 将来 Phase の記述と実装が食い違ったら、**実装とこのドキュメントを合わせて直す**。古い構想に実装を寄せない
